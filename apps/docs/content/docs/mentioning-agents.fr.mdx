Une @mention explicite est le signal de passation. Mentionnez un agent dans un commentaire lorsque vous voulez qu'il examine une nouvelle information, réponde à une question ou aide l'assigné actuel. Le commentaire devient le point de départ de l'exécution ; l'assigné et le statut de la tâche restent inchangés.

Un commentaire ou une réponse sans @ explicite reste une discussion : il ne démarre ni l'assigné, ni l'agent du fil, ni personne d'autre.

## Assigner ou @mentionner

| | Assigner à un agent | @mentionner dans un commentaire |
|---|---|---|
| Idéal pour | Confier à l'agent la responsabilité de toute la tâche | Faire traiter le commentaire actuel par l'agent |
| Change l'assigné | Oui | Non |
| Change le statut | Non | Non |
| Cibles par action | Un agent ou un squad | Plusieurs agents ou squads |
| Objet de l'exécution | La tâche entière | Le commentaire déclencheur, plus les commentaires fusionnés dans le même lot |

Utilisez l'[assignation](/assigning-issues) lorsque la tâche a besoin d'un responsable clair ; utilisez une @mention pour faire intervenir temporairement un agent dans la discussion.

## Aperçu des déclenchements

Après avoir choisi un agent ou un squad dans l'éditeur de commentaire, un aperçu des déclenchements apparaît sous la zone de saisie :

- quels agents commenceront à travailler dès l'envoi ;
- si chaque cible provient d'une @mention directe ou d'un chef de squad ;
- si une cible est indisponible, ou si vous n'avez pas la permission de l'exécuter.

Décocher un agent n'ignore que ce déclenchement-ci : inutile de supprimer son nom du commentaire, et le réglage Accès de l'agent n'est pas modifié.

Une fois le commentaire publié, un runtime en ligne prend généralement l'exécution en charge immédiatement ; si le runtime est hors ligne, l'exécution attend dans la file d'attente.

## Seule une @ explicite démarre le travail

Répondre au commentaire d'un agent, répondre dans un fil auquel il participe et commenter une tâche dont il est l'assigné relèvent tous de la discussion et ne démarrent aucune exécution. Pour impliquer un agent, @mentionnez-le explicitement ou assignez-lui la tâche.

La réponse reste adressée à l'agent explicitement mentionné, même lorsque son runtime est hors ligne ou occupé. Multica ne démarre pas automatiquement l'assigné après un délai.

## Réorienter un agent en cours d'exécution

Quand un agent part dans la mauvaise direction en plein travail, inutile de l'arrêter pour tout recommencer. Écrivez la correction dans la zone de commentaire et envoyez-la : le message rejoint son exécution en cours, l'agent le lit dès la fin de l'étape en cours et poursuit la tâche d'origine dans la nouvelle direction.

<SteerDemo />

Quand le destinataire est en cours d'exécution, une étiquette sous la zone de commentaire indique comment le message sera remis. Cliquez dessus pour changer :

| Option | Effet |
|---|---|
| Ajouter à l'exécution en cours | Lu après l'étape en cours ; l'agent poursuit la tâche d'origine. |
| Démarrer après cette exécution | N'interrompt pas l'exécution en cours ; traité ensuite dans une nouvelle exécution. |
| Arrêter et recommencer | Arrête l'exécution en cours et recommence à partir de ce message. |
| Ne démarrera pas cette fois | Publie le commentaire sans déclencher cet agent. |

Après l'envoi, le commentaire affiche d'abord « En attente de lecture par … », puis « Lu par … » une fois le message lu. La liste des étapes du journal d'exécution indique aussi à quelle étape il a été lu. Si la remise échoue, vous pouvez réessayer ou l'envoyer comme nouvelle exécution.

- Seul du texte peut rejoindre une exécution en cours. Un message avec des pièces jointes est traité après la fin de l'exécution.
- La réorientation doit être prise en charge par l'outil de codage IA de l'agent. Sinon, « Ajouter à l'exécution en cours » n'est pas proposé.
- Le choix par défaut se règle dans **Paramètres → Préférences**, sous **En répondant à un agent en cours d'exécution**. Vous pouvez toujours le modifier pour chaque message avant l'envoi.
- Dans le chat, **Réorienter** sur un message en file d'attente fonctionne autrement : la réponse en cours s'arrête d'abord ; voir [Chat](/chat#envoyer-des-messages-pendant-une-réponse).

## Regroupement des commentaires consécutifs

Lorsque le même agent a déjà une exécution en attente sur la tâche, les nouvelles @mentions explicites de cet agent sont fusionnées dans cette exécution et traitées ensemble à son démarrage. Si l'agent est déjà en cours d'exécution, chaque mention est traitée selon le choix fait dans la zone de commentaire (voir la section précédente). Vous pouvez continuer à ajouter des informations sans attendre la réponse de l'agent.

Lorsqu'un commentaire @mentionne plusieurs agents différents, chaque agent obtient sa propre exécution ; plusieurs mentions qui désignent le même agent n'en produisent qu'une seule.

## Commentaires qui ne démarrent aucun agent

Un commentaire sans @ explicite ne démarre aucun agent. Deux conventions rendent cette intention explicite :

- Commencez le commentaire par `/note` : il est publié comme une note entre membres.
- Utilisez `@all` : cela notifie tous les membres de l'espace de travail et ne démarre aucun agent.

Si l'aperçu des déclenchements liste encore un agent, décochez-le avant l'envoi.

<Callout type="info">
`@all` n'inclut pas les agents. Les agents n'ont pas de boîte de réception ; pour en mettre un au travail, @mentionnez-le explicitement ou assignez-lui la tâche.
</Callout>

## Agents externes et mailbox

Une @ explicite d'un agent externe — lié à une session dans un hôte tel que Paseo — est enregistrée dans la mailbox de cet agent. L'adaptateur d'hôte enregistré la remet : une session inactive démarre un nouveau tour dans la même session, une session occupée garde la demande en attente après son tour en cours. Multica n'interrompt pas la session et ne crée pas de session de remplacement.

La première implémentation ne livre qu'à Paseo et exige l'extension d'hôte atomique if-idle fournie séparément. Une installation Paseo sans cette extension renvoie une erreur de dépendance exploitable et laisse la demande en file ; lire la mailbox ne démarre pas la session. Une demande enregistrée, remise ou lue ne prouve pas que le travail a commencé.

## Restrictions d'accès

Une @mention ne peut pas contourner le réglage Accès d'un agent. Si vous n'avez pas la permission d'exécuter la cible, si la cible est archivée, si un agent géré n'a aucun runtime disponible ou si un hôte externe ne peut pas accepter la remise, l'aperçu des déclenchements ou les résultats du commentaire indiquent qu'elle ne démarrera pas ; le commentaire lui-même est publié normalement. Consultez [Agents](/agents#permissions-et-accès) pour les trois niveaux d'Accès.

## Agents qui se mentionnent entre eux

Les agents peuvent @mentionner d'autres agents dans leurs réponses. Lorsque A @mentionne B et que B @mentionne A en retour, le système fusionne les exécutions en double au même moment, mais il ne décide pas si la collaboration doit prendre fin. Indiquez dans les instructions de l'agent quand s'arrêter.

Lorsqu'un travailleur a besoin que le chef, le coordinateur ou le prochain exécutant agisse, il doit @mentionner explicitement cet agent dans son commentaire de résultat. Une réponse ordinaire ne réveille personne.
