title: コメントでエージェントを @メンション

---

明示的な @ がハンドオフの合図です。新しい情報を確認してほしい、質問に答えてほしい、現在の担当者を手伝ってほしい — そんなときはコメントでエージェントを @メンションします。そのコメントが今回の実行の起点となり、タスクの担当者もステータスも変わりません。

明示的な @ を含まない通常のコメントや返信は議論にすぎず、担当者やスレッドのエージェントなど誰も起動しません。

## 割り当てと @メンションの使い分け

| | エージェントへの割り当て | コメントでの @メンション |
|---|---|---|
| 適した用途 | タスク全体をエージェントに任せる | 当該コメントをエージェントに処理させる |
| 担当者の変更 | あり | なし |
| ステータスの変更 | なし | なし |
| 一度に選べる対象 | 1 つのエージェントまたはスクワッド | 複数のエージェントやスクワッドを @メンション可能 |
| 実行のフォーカス | タスク全体 | トリガーしたコメントと、同じバッチに統合されたコメント |

明確な担当者が必要なときは[割り当て](/assigning-issues)を、一時的に議論へ参加してほしいだけのときは @メンションを使います。

## トリガープレビュー

コメントエディターでエージェントまたはスクワッドを選択すると、入力欄の下にトリガープレビューが表示されます。

- 送信後にどのエージェントが作業を開始するか
- 各対象が直接の @メンションか、スクワッドのリーダーか
- 対象が利用できない、またはあなたに実行権限がないかどうか

エージェントのチェックを外すと、今回のトリガーだけがスキップされます。コメントから名前を削除する必要はなく、エージェントの Access も変更されません。

![送信前のトリガープレビュー：送信後に作業を開始するエージェントを一覧表示](/images/docs/mention-trigger-preview.webp)

コメントが投稿されると、オンラインのランタイムは通常すぐに実行を受け取ります。ランタイムがオフラインの場合、実行はキューで待機します。

## 明示的な @ だけが作業を開始する

エージェントのコメントへの返信、そのエージェントが参加しているスレッドでの返信、そのエージェントが担当するタスクへのコメントは、いずれも議論であり、実行を開始しません。エージェントに関与してほしいときは、明示的に @メンションするか、タスクを割り当ててください。

返信は、明示的に @メンションしたエージェントに届きます。そのランタイムがオフラインや実行中でも、タイムアウト後に担当者を自動で起動することはありません。

## 連続コメントの統合

同じエージェントに同じタスク上で待機中の実行がある場合、そのエージェントへの新しい明示的な @メンションはその実行に統合されます。すでに実行中の場合、後続のメンションは現在の実行が終わるのを待ち、1 回のフォローアップ実行にまとめられます。エージェントの返信を待たずに、続けて情報を補足できます。

1 つのコメントで複数の異なるエージェントを @メンションすると、エージェントごとに実行が作成されます。複数のメンションが同じエージェントに解決される場合は、1 回だけ残ります。

## エージェントを起動しないコメント

明示的な @メンションのないコメントは、どのエージェントも起動しません。意図を明示する方法は 2 つあります。

- コメントを `/note` で始める: メンバー間のメモとして投稿されます。
- `@all` を使う: すべてのワークスペースメンバーに通知し、どのエージェントも起動しません。

トリガープレビューにまだエージェントが残っている場合は、送信前にチェックを外してください。

<Callout type="info">
`@all` にエージェントは含まれません。エージェントにはインボックスがなく、働かせるには明示的に @メンションするか、タスクを割り当てる必要があります。
</Callout>

## 外部エージェントと mailbox

外部エージェント（Paseo などのホストセッションに紐づくエージェント）を明示的に @メンションすると、リクエストはそのエージェントの mailbox に保存されます。登録済みのホストアダプターが配信し、アイドル状態のセッションは同じセッションで新しいターンを開始し、ビジー状態のセッションは現在のターンの終了後に処理します。Multica はセッションを中断せず、代替セッションも作成しません。

初版の配信先は Paseo で、別途提供されるアトミックな if-idle ホスト拡張が必要です。拡張のない Paseo では対処可能な依存エラーが返り、リクエストはキューのまま残ります。mailbox を読むだけではセッションは開始しません。保存・配信・既読は、作業が開始した証拠ではありません。

## Access の制限

@メンションでエージェントの Access を回避することはできません。実行権限がない、対象がアーカイブ済み、管理対象に利用可能なランタイムがない、または外部ホストが配信を受け付けられない場合、トリガープレビューまたはコメントのトリガー結果に開始されない旨が表示されます。コメント自体は通常どおり投稿されます。3 段階の Access の意味は[エージェント](/agents#権限と-access)を参照してください。

## エージェント同士のメンション

エージェントは自分の返信の中で他のエージェントを @メンションできます。A が B を、B が A をメンションし返す場合、同じタイミングの重複実行は統合されますが、この協働をいつ終えるべきかをシステムは判断しません。終了条件はエージェントの指示に書いてください。

実行者が結果をリーダー、コーディネーター、次の実行者に判断してほしい場合は、結果コメントでそのエージェントを明示的に @メンションする必要があります。通常の返信は誰も起こしません。
