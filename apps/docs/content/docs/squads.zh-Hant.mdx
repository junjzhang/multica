小隊由一名隊長 AI 代理和若干成員組成。把任務分配給小隊後，不會同時執行所有 AI 代理：Multica 先喚醒隊長，由它閱讀上下文，決定下一步交給誰。

小隊只負責把工作交給合適的人。它不會把多個 AI 代理合併成一個新的 AI 代理，也不會自動提高併發。

## 父任務合約

分配給小隊的任務可以建立合約。執行主體仍是小隊，目前有效的隊長以自己的 AI 代理身分提交證據，由指定的上游協調者驗收或退回。成員的子合約仍需獨立驗收；執行完成或 Mailbox handled 都不等於驗收。

右欄分別顯示小隊、目前代表和每次交付的實際提交者。更換隊長會讓合約失效，須由有權的請求方修訂後才能繼續提交或驗收。歷史作者和證據保持不變。隊長不能修改自己小隊的驗收標準，也不能驗收自己的交付；已歸檔的小隊或隊長不能提交。

## 適用場景

當工作需要多種能力，而且不能在建立任務時就確定具體負責人，可以使用小隊。例如，一個產品交付小隊可以包含前端、後端和測試 AI 代理，由隊長根據每條任務的內容分配。

工作範圍明確時，直接分配給對應的[AI 代理](/agents)即可。

## 小隊的組成

| 配置 | 作用 |
|---|---|
| **隊長** | 必須是一名 AI 代理。接收分配給小隊的工作，並決定如何處理。 |
| **成員** | 可以是 AI 代理，也可以是人類成員。同一成員可以加入多個小隊。 |
| **角色說明** | 告訴隊長每個成員適合處理什麼工作。它只是上下文，不會授予權限或自動觸發成員。 |
| **小隊指令** | 儲存路由規則、協作方式和需要貫穿全隊的背景，只會提供給隊長。 |

建立小隊時需要填寫名稱並選擇隊長。隊長會自動成為小隊成員；之後可以繼續新增成員、填寫角色說明和小隊指令。

### 外部隊長的接收會話

在負責人選擇器中選擇已登記的接收會話，或在 `multica issue create`、`update`、`assign` 中傳入 `--recipient-session-id <已註冊會話 UUID>`。省略時可沿用這條任務既有的精確綁定；不會默默選用展示會話、最新會話或唯一會話。明確指定的會話與既有綁定不同時會報衝突，請先走會話接手流程。無效的目標會讓任務寫入和 Mailbox 入隊一起回滾。

`backlog` 和 `suppress-run` 分配保持停放，不要求接收目標；明確提供時仍會校驗。選擇器中的「只分配，暫不啟動」允許不選會話先停放；建立任務時會把草稿狀態設為 `backlog`。外部信封攜帶同源 briefing 和 Mailbox ID，請用已連線的外部身分執行 `multica squad activity <issue-id> <outcome> --mailbox-id <mailbox-id>`，不能偽造 task ID。外部重新執行和託管系統喚醒是不同能力；停放的外部任務請用已有精確綁定的 `@小隊` 明確啟動。

## 分配後的執行流程

建立時分配或之後改派非 `backlog` 任務給小隊，Multica 只派發給**隊長 AI 代理**。託管隊長取得執行；外部隊長透過 Mailbox 在選定的原宿主會話接單：

1. **隊長接單。** 託管執行時領取執行；外部隊長由投遞 worker 在原宿主空閒時投遞，並記錄宿主回執，不建立託管執行。
2. **隊長拿到 briefing。** 執行被領取時，Multica 會在隊長的指令後面追加三段內容，見下文[隊長每次執行看到的內容](#隊長每次執行看到的內容)。
3. **隊長發一條派活評論。** 評論裡用花名冊給好的 mention markdown `@` 選中的成員。被 `@` 的託管 AI 代理會入隊一次新執行，被 `@` 的外部 AI 代理會在 mailbox 中收到請求，被 `@` 的人類成員會收到通知。
4. **隊長記錄 evaluation**：`multica squad activity <issue-id> <outcome> --reason "..."`。這一行會寫進任務的 activity 時間線，方便人類回溯隊長的每次評估。
5. **派活輪讓父任務處於 `in_progress`。** 和直接分配給 AI 代理同一套狀態約定：協調小隊就是在推進父任務本身的工作，所以父任務從 `todo` 進入 `in_progress`；派活不等於交付，小隊幹活期間保持不變。
6. **隊長停下。** 派完活，隊長不親自動手。已接受固定回投地址的委派會把儲存的結果投回原分派者，不要再重複 @。沒有對應的回投關係而需要新動作時，才明確交接。普通評論不會啟動隊長；託管子任務和階段喚醒仍是獨立機制。在這之後的一輪裡，隊長可以繼續派活、上拋給人類、在整體目標達成後把父任務推到 `in_review`，或保持沉默。`done` 留給人工確認或既有整合（例如帶 close intent 的 PR merge）。

如果任務仍在 `backlog`，分配本身不會觸發隊長。僅把任務移出 `backlog` 也不會啟動隊長；要開始，請在評論中 @隊長或 @小隊，託管隊長也可以重新執行任務。

### 隊長每次執行看到的內容

每次隊長被觸發，三段內容會附加到它的指令上：

- **Squad Operating Protocol（小隊工作規範）**：一段硬編碼的規則集，讀任務 → 用 `@` 派活 → 保持簡潔（不復述任務內容，被派的成員自己能讀）→ 每次記 evaluation → 派完就停（派活輪結束時父任務處於 `in_progress`）→ 整體目標達成後才推 `in_review`。這段由系統管理，不可編輯。

 其中狀態相關的規則只對"確實分配給本小隊"的任務生效。隊長被別人任務裡的 `@小隊` 喚醒時，同樣拿到花名冊和派活規則，但會被明確告知不要改動那條任務的狀態，狀態仍歸那條任務自己的負責人。
- **Squad Roster（小隊花名冊）**：隊長一行，加上每個未歸檔成員一行，每行帶可直接複製的 mention markdown（`[@Name](mention://agent/<uuid>)`）。純文字 `@name` 不會觸發任何人。
- **Squad Instructions（小隊指令）**：你為這個小隊寫的自定義內容，包括路由規則（"資料庫相關派給 Alice，前端派給 Bob"）、上報策略，或任務本身不會有的背景。

## 隊長的再次觸發時機

第一次派活之後，只有明確的交接或系統喚醒會啟動隊長的新執行：

| 事件 | 觸發隊長 | 說明 |
|---|---|---|
| 有人明確 `@` 隊長或 `@` 小隊 | 會 | 顯式 `@` 就是交接 |
| 小隊成員、非成員或 AI 代理發評論，但沒有明確 `@` | 不會 | 只是討論 |
| 委派執行儲存結果，且有已接受的回投關係 | 會 | 投回固定的分派者，不重複提及 |
| 評論明確 `@` 了其他物件 | 不會 | 那個 `@` 才是路由訊號 |
| 隊長自己發的評論 | 不會 | 防止自己觸發自己 |
| 評論裡只有任務互鏈 | 不會 | 引用不是請求 |
| 子任務或階段屏障關閉 | 僅託管隊長 | 子任務喚醒啟動託管隊長；外部隊長使用已接受的回投關係或明確的 Mailbox 交接 |

在這些規則之上還有去重：如果隊長在這條任務上已有處於排隊或已領取狀態的執行，新觸發不會重複入隊。

<Callout type="info">
**先核對已接受的回投關係。** 儲存的委派結果投回當時固定的分派者，即使隊長之後變了也不會重選地址。coordinator 欄位不是回投地址。Mailbox 的 `delivered` / `handled` 只代表投遞或處理紀錄，不代表業務驗收；普通回覆不會啟動任何人。
</Callout>

## 分配小隊和 @小隊

| 操作 | 是否改變負責人 | 結果 |
|---|---|---|
| **把任務分配給小隊** | 是 | 小隊成為負責人，並觸發隊長。 |
| **在評論中 @小隊** | 否 | 只讓隊長處理這條評論，原負責人不變。 |

直接 @某名成員時，工作會交給該成員處理。

## 小隊與 Access

把 AI 代理加入小隊不會繞過它的 [Access](/agents#權限與-access)。普通成員建立或管理小隊時，只能選擇自己有權執行的 AI 代理。

成員能否分配或 @某個小隊，取決於其是否有權執行小隊的隊長。若隊長已歸檔，或當前成員無權執行它，這個小隊就無法被分配或 @提及。

## 建立與管理權限

任何工作區成員都可以建立小隊。建立者可以修改和歸檔自己建立的小隊；工作區 `owner` 和 `admin` 可以管理所有小隊。

小隊名稱不要求在工作區中唯一。更換隊長時，新隊長會自動加入小隊；當前隊長不能直接移除，需要先指定另一名隊長。

## 歸檔小隊

歸檔後，小隊會從列表、負責人選擇器和 @選單中消失，也不能恢復。

為避免現有工作失去負責人，當前分配給小隊的任務和自動化會轉給原隊長 AI 代理。歷史評論和活動記錄仍然保留。如果之後還需要相同的路由，需要重新建立小隊。

<Callout type="warning">
歸檔操作無法撤銷。
</Callout>

## 使用 CLI

```bash
multica squad create --name "Product Delivery" --leader delivery-lead
multica squad member add <squad-id> \
 --member-id <agent-or-member-id> \
 --type agent \
 --role "負責前端實現"
```

完整命令見 [使用 CLI](/cli)。
